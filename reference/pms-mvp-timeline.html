M2
Reservations, Rate Engine & Rate Resolver
Weeks 5–8 4 weeks Rate Resolver NEW
The booking lifecycle and pricing engine. The Rate Resolver is built as an isolated NestJS service from day one — never replicated in the frontend. Every screen that shows a price calls it. This single architectural decision prevents rate drift and makes all pricing auditable from the start.
▣
Rate Resolver Service NEW
Backend-only — frontend never calculates rates
BEDB
▼
Architecture Rule
RateResolverService in NestJS — pure, stateless, injectable
Rule priority order: manual override → corporate → promo → negotiated → seasonal → weekend → base
Every calculation auto-logged to RateAuditLog table
Response always includes ruleApplied field (type, planName, adjustmentApplied)
Frontend RatePreview component: calls endpoint on mount, re-fetches on prop change, never caches locally
Endpoints
POST/rate-resolver/calculate
Returns nightlyRate, totalWithTax, ruleApplied, per-night breakdown. Called by: reservation create, walk-in, folio post, check-in, reg card gen, RMS comparison
GET/rate-resolver/audit?reservationId=
Full rule-resolution trace per reservation for dispute handling
